## 0. 前置检查（缺一不可）

| 检查项 | 通过标准 | 不通过怎么办 |
| --- | --- | --- |
| 数据线 | 普通模式下插电脑有提示音，`adb devices` 能列出设备 | 换线（见 `07-blockers.md`） |
| OTG 转接头 | **必须拔掉** | OTG 会让手机进 Host 模式，9008 进不去 |
| 电量 | ≥ 50% | 先充电 |
| 固件版本 | 本机实测 `R9sk_11_A.37_191127` | 刷机包必须匹配 `R9sk` 机型与 A.xx 版本线 |

| 电脑环境 | Windows 10/11；**WHQL 签名的 9008 驱动已于 2026-11-22 装好**（`oem139.inf`，v2.1.1.0） | 无需关闭驱动签名强制；见 `evidence/2026-11-22-qdloader-driver.txt` |

## 2. 进入 9008

```
1. 手机完全关机（不是重启，是关机）
2. 按住 音量+ 和 音量- 不放
3. 插入 USB 线（连电脑）
4. 保持按住约 5 秒，然后松开
```

> **卡在 OPPO logo 时怎么真正关机（实测）**：**先拔掉数据线**，再同时按住 **音量+ 和 电源键** 约 10 秒，直到屏幕全黑。
> 插着线只按电源键是关不掉的（会落回 OPPO 充电模式 / 无反应）。

**判断标准**：

| 阶段 | 设备管理器显示 |
| --- | --- |
| 刚插入 | `QUSB_BULK` 或 `Qualcomm HS-USB QDLoader 9008 (COMx)`（未装驱动时可能带黄色感叹号） |
| 装好驱动 | `Qualcomm HS-USB QDLoader 9008 (COM3)` 之类，端口号记下来 |

如果**设备管理器毫无反应** → 物理层没通，回到 `07-blockers.md`，不要继续。

## 3. 刷写步骤（先只动 recovery）

```
1. 先运行一次 MsmDownloadTool-0.exe（授权绕过），关闭
2. 打开 MsmDownloadTool.exe，选择项目号 16027（R9sk），「开始」按钮应可点击
3. 按 F5 进入分区选择界面
4. 全不选，先只勾选：
      recovery  → TWRP 包里的 recovery.img
5. 取消「下载完成后自动重启」（如果有这个选项）
6. 点「开始」，等待进度条走完（通常 1–3 分钟）
7. 刷完自动重启时立刻按住 音量-；若卡 logo，**拔线 + 音量+ + 电源 10 秒**强制关机，
   再立刻按住 音量-（只按电源键关不掉）
```

> **关于 aboot**：A.37（≥ 170112）按公开教程「建议加刷」TWRP 包里的
> `emmc_appsboot.mbn`，否则新版 TWRP 可能被官方 aboot 的签名校验挡住。
> 但 aboot 是风险最高的分区（刷错机型会进不了系统）。**建议先只刷 recovery**：
> 能进 TWRP 就不动 aboot；进不去再重新进 9008，补刷 aboot。
> 无论哪种情况，都**不要**用 R9s / R9st 的 aboot。

### 为什么先只刷 recovery

- `recovery`：TWRP，用来刷 root 包和备份；这一步失败也还能重进 9008。
- `aboot`：把锁定的引导替换成解锁版；**只在 TWRP 进不去时再补刷**。
  它是风险最高的分区，刷错机型可能直接不开机。
- **不动 `boot` / `system` / `userdata`**：降低变砖和数据丢失风险。

> 如果 TWRP 包里的 `emmc_appsboot.mbn` 与你的固件版本不匹配，**先别刷**。
> 版本错配是「刷完进不了系统」的头号原因。

## 4. TWRP 里第一件事：备份

进 TWRP 后，**先备份再刷 root**：

```
Backup → 勾选：
  ☑ EFS        ← IMEI / 基带，丢了不可恢复
  ☑ Modem      ← 基带固件
  ☑ Persist    ← 传感器校准、指纹等
  ☑ Boot
```

备份存到外置 SD 卡或 OTG U 盘（如果 TWRP 支持），**不要只存内置存储**——
万一后面要格式化 data，内置备份一起没。

## 5. 刷 root

| 方案 | 适用性 | 说明 |
| --- | --- | --- |
| **SuperSU 2.82** | ✅ 最稳 | 老平台兼容性最好，但 2017 年后停更 |
| **Magisk 20.x / 21.x** | ⚠️ 可用 | 支持 Android 6，但模块生态有限；新版 Magisk 已放弃 Android 6 |
| 其他「一键 root 包」 | ❌ 不要用 | 来源不明，常捆绑推广 |

刷完重启，验证：

```bash
adb shell        # 或 Termux 里
su -c id         # 应返回 uid=0(root)
```

## 6. 风险清单（认真看）

| 风险 | 概率 | 后果 | 缓解 |
| --- | --- | --- | --- |
| **刷错 aboot 变砖** | 中 | 进不了 fastboot | 只要还能进 9008 就能救；版本号必须核对 |
| **破解版工具带毒** | 中高 | 电脑被植入木马 | **在虚拟机 / 断网环境跑**，别在主力机 |
| **线刷包版本不匹配** | 中 | 基带丢失、无法开机 | 严格按 `R9sk_11_A.xx` 找包 |
| **TWRP 不兼容** | 中 | 触摸失灵 / 无法挂载 | 换 R9sk 专用版本，别用 R9s 的 |
| **备份丢失** | 低 | IMEI 丢失，无法通话 | 先备份 efs/modem/persist 到外部存储 |
| **dm-verity 校验失败** | 中 | 开机卡 logo | 刷完 root 后可能需要禁用 verity（TWRP 选项） |
| **保修** | — | 2016 年机器，保修早过 | 无所谓 |

### 真正的致命点

**「连 9008 都进不去」** 才是不可救的。只要 9008 还能枚举，理论上任何分区错误都能重刷。
所以：

- 进 9008 之前，先确认**普通模式 USB 是通的**
- 如果普通模式都不通，9008 大概率也不通（同一组 D+/D-）

## 7. 救砖路径

| 症状 | 处理 |
| --- | --- |
| 卡 logo | 进 TWRP → 恢复 boot/system 备份，或重刷官方 boot |
| 进不了 fastboot | 重新进 9008，刷回官方 `aboot` |
| 完全黑砖 | 9008 + 官方完整线刷包（全分区） |
| 9008 也进不去 | 检查线/口/尾插；尾插损坏需拆机 |

---

## 8. root 之后立刻要做的事

1. **验证 root**：`su -c id`
2. **装 Termux 的 root 源**：`pkg install openvpn`（root 源里唯一相关的网络包）
3. **测 `/dev/tun`**：`su -c 'ls -l /dev/tun'` + 尝试 `openvpn` 建隧道
4. **再谈 ZeroTier**：官方无 Termux 包，需要自行交叉编译；先用 OpenVPN 验证 TUN 通路
5. **记录**：把 `su -c getprop` 的输出存一份，和 root 前对比

### 9.2 进 9008（公开教程一致）

1. 关机（不是重启）。
2. 同时按住 音量+ 和 音量-。
3. 插入 USB，保持约 5 秒。
4. 设备管理器出现 `QUSB_BULK`（未装驱动）或
   `Qualcomm HS-USB QDLoader 9008 (COMx)`。

> **R9s/R9sk 没有 fastboot**（OPPO 自 R7 起移除），不能靠
> `fastboot oem unlock` 解锁；9008 是唯一入口。

> **进不去怎么办**：后备是深刷线（D+ 短 GND）或拆机短接尾插/主板 TP。
> 关机插线，短接 3–5 秒后断开；看到 9008 端口就立即断开短接。
> 这属于拆机级操作，风险高，非必要不用。

### 9.5 替代路线：不碰改版 Windows exe（研究级）

1. 用 `bkerler/oppo_decrypt` 的 `ofp_qc_decrypt.py` 从 OFP 提取
   `prog_firehose_ddr.elf`（厂商签名 loader）。
2. 用 `bkerler/edl` 走 Sahara/Firehose，按 `rawprogram0.xml` 只写
   `recovery`（必要时 `aboot`）。
3. 若 loader 报
   `Only nop and sig tag can be received before authentication`，
   `HsOjo/edl-noauth-kit` 的 blob2 在**全新 9008 会话**里可通过
   （challenge 为空）；每次操作前重新进 9008。
4. **QFIL 路线**：Qualcomm QFIL / QSaharaserver + fh_loader 可直接用
   OFP 里的 `rawprogram0.xml` + 签名 firehose，不依赖 OPPO 工具授权。
   XDA 有 R9s 的案例标题（正文 403，细节未核实），仅作线索。

> 这条路不运行来源不明的 exe，但步骤多、需要 Python/libusb；
> 该 kit 只在 macOS + SDM660 上验证过，**Windows 未实测**。

#### 9.5.1 loader 已找到：R9s 签名，R9sk 兼容性待实测（2026-11-21）

公开 loader 集合里能直接拿到 OPPO 8953 的全功能 programmer，不必先下 1.3GB 整包：

| 文件 | 大小 | MD5 | 说明 |
| --- | --- | --- | --- |
| `prog_emmc_firehose_8953_ddr_oppo_r9s.mbn` | 359048 | `1ded75bb22c4e9334462f8be717ac907` | ELF32；R9s 签名；**首选** |
| `prog_emmc_firehose_8953_oppo_r9s.mbn` | 359112 | `e0165a731ebb573aa66be7c99023264c` | ELF32；同签名组的另一构建 |
| `prog_emmc_firehose_8953_ddr.mbn` | 359048 | `6e7aac18a7df36697e18a8cc0081ce70` | ELF32；同签名组，通用名 |
| `MSM8953.mbn` | 363164 | `333fbe3da5a85898abde77fe03ad4988` | **小米签名，不可用** |

- 三个可用 loader 都含 `configure / getstorageinfo / program / erase / patch /
  peek / read / firmwarewrite / erasecust`，且**没有** `Only nop and sig`
  这类 Firehose 二次认证字符串。
- 它们共用同一张 OPPO 根证书（temblast 索引：SHA256 `90864ecb91f86a1c`，
  SHA384 `ca93d5300bc053d7`），证书 CN 是 **16017（R9s）**；公开索引里
  **没有** 16027（R9sk）专用 loader。
- R9sk 与 R9s 同属 CPH1607 家族，设备 OTA 字符串是
  `R9s_11.A.37_0370_201911271523`，固件基线共用。**推断** R9sk 接受同一
  OPPO 根证书签名的 loader；最终要看 9008 Sahara 握手时设备 QFPROM 的
  PK_HASH 是否匹配。
- 若 Sahara 拒绝，回退到 R9sk **A.18**（1.53GB，MD5
  `8171554911a97008e410b385667fc9f2`）或 **A.22**（1.30GB，标题明确带
  `firehose_8953`）包内的 loader。

> 结论：**loader 这一格已经从“缺文件”变成“有一个高概率可用、待 9008 实测的
> 文件”**。真正的前置条件仍是 B1（USB 枚举）。

## 11. 开源 edl 实操清单（2026-11-22，PC 端已就绪）

> 本节取代 §3 的 MsmDownloadTool 流程。所有命令在
> `C:\MyFile\AICoding\oppo-r9sk-root\work\edl` 下执行。
> 9008 驱动是串口 `qcusbser.sys`，所以用 `--serial`；若自动选端口失败，
> 用 `--portname \\.\COMx`（x = 设备管理器里 `Qualcomm HS-USB QDLoader 9008` 的端口号）。

### 11.1 进入 9008 并确认端口

1. 手机完全关机（不是重启）。
2. 按住 **Power + Vol+ + Vol-** 三键不放，插入 USB 线（连 PC 后置口），保持约 5 秒后松开。
3. 设备管理器应出现 `Qualcomm HS-USB QDLoader 9008 (COMx)`；记下 `COMx`。
   若毫无反应 → 物理层没通，回到 `07-blockers.md`，不要继续。

### 11.2 只读探测（不改手机）

```bat
python edl.py --serial --loader C:\MyFile\AICoding\oppo-r9sk-root\work\loaders\prog_emmc_firehose_8953_ddr_oppo_r9s.mbn printgpt
python edl.py --serial --loader C:\MyFile\AICoding\oppo-r9sk-root\work\loaders\prog_emmc_firehose_8953_ddr_oppo_r9s.mbn getstorageinfo
```

确认 Sahara/firehose 握手成功、分区表能列出来，且能看到 `aboot` / `recovery` /
`efs` / `modem` / `persist` 等分区名（以 `printgpt` 实际输出为准）。

### 11.3 只读备份（先备份后写）

在 `work\backup\` 下建立目录，逐分区读回（分区名按 `printgpt` 校正）：

```bat
python edl.py --serial --loader <loader> r aboot    C:\MyFile\AICoding\oppo-r9sk-root\work\backup\aboot.orig.bin
python edl.py --serial --loader <loader> r recovery C:\MyFile\AICoding\oppo-r9sk-root\work\backup\recovery.orig.bin
python edl.py --serial --loader <loader> r efs      C:\MyFile\AICoding\oppo-r9sk-root\work\backup\efs.orig.bin
python edl.py --serial --loader <loader> r modem    C:\MyFile\AICoding\oppo-r9sk-root\work\backup\modem.orig.bin
python edl.py --serial --loader <loader> r persist  C:\MyFile\AICoding\oppo-r9sk-root\work\backup\persist.orig.bin
```

**备份校验**：每个 `.bin` 大小应 > 0 且与 `printgpt` 的分区大小一致；留好哈希。
任意一个读不出来 → 停止，不要写。

### 11.4 写入（仅在备份验证可读后）

方式 A——Qfil（按包内 XML，只写 `aboot` + `recovery`，会顺带修 GPT 头 CRC）：

```bat
python edl.py --serial --loader <loader> qfil C:\MyFile\AICoding\oppo-r9sk-root\work\twrp-r9s\rawprogram0.xml C:\MyFile\AICoding\oppo-r9sk-root\work\twrp-r9s\patch0.xml C:\MyFile\AICoding\oppo-r9sk-root\work\twrp-r9s
```

方式 B——更可控地分步写（推荐，先只写 `recovery` 验证能否进 TWRP，不动 `aboot`）：

```bat
python edl.py --serial --loader <loader> w recovery C:\MyFile\AICoding\oppo-r9sk-root\work\twrp-r9s\recovery.img
```

若能进 TWRP，就不必写 `aboot`；若被官方 aboot 签名校验挡住，再补写
（**写前已备份原机 `aboot`**）：

```bat
python edl.py --serial --loader <loader> w aboot C:\MyFile\AICoding\oppo-r9sk-root\work\twrp-r9s\emmc_appsboot.mbn
```

### 11.5 重启进 TWRP

```bat
python edl.py --serial --loader <loader> reset
```

拔线，按住 **Power + Vol-** 到振动/OPPO splash 后进 recovery。进 TWRP 后
第一件事仍是 §4 的备份（EFS / Modem / Persist / Boot）。

> 铁律：**不碰 userdata / efs / modem / persist / system**；`rawprogram0.xml`
> 实测只写 `aboot` 与 `recovery`，`patch0.xml` 只修 GPT 头/CRC。
