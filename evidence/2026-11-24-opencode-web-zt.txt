## 5. 本轮修掉的三个真问题

### 5.1 `opencode serve` 起了又没了 —— 缺 `setsid`

现象：日志里出现过 `server listening on http://0.0.0.0:4300`，几秒后进程消失、端口没了。
原因：`serve` 是**前台进程**，用 `&` 放在 `adb shell`/`service.d` 的子 shell 里时，
调用者退出会把它连带杀掉（进程组/会话一起收）。
修法：`/usr/bin/setsid /usr/bin/setpriv --reuid=2000 … opencode serve …`，进程 `ppid=1` 后稳定常驻。

### 5.2 ZeroTier online 但局域网/虚拟网互不可达 —— Android 策略路由

现象：`zerotier-cli info` 是 ONLINE、`listnetworks` 是 OK，但手机 ping 不通任何 zt 地址，
PC 访问 `192.168.193.5:4300` 失败；`tcpdump -i wlan0` 只看到手机在跟 planet 服务器（185.152.67.145、
103.195.103.66 等）打 UDP 9993，从未与局域网内的对端（192.168.2.161）直接通信。

原因：Android 的 netd 只给进程查 per-network 表（`ip rule … lookup wlan0`），而
wlan0 表里只有默认路由，**main 表里才有 `192.168.193.0/24 dev ztyqb623ap`**。
没有额外规则时，发往 zt 子网的包被 wlan0 的默认路由带走、然后在 LAN 上被丢弃。

修法：`ip rule add to 192.168.193.0/24 lookup main priority 21000`。
加了之后同一份 `peers` 输出里立刻出现 `8c9fe6aa1c … 192.168.2.161/47197`（DIRECT，14 ms），
PC 访问 ZT 地址 89 ms。

### 5.3 开机脚本里规则永远加不上 —— Android 7.1 没有 `awk`

`ip -4 route show | awk …` 在 service.d 里恒为空。排查发现：

```
$ ls /system/bin/awk
/system/bin/awk: No such file or directory
$ busybox --list | grep -x awk
awk
```

Android 7.1 的 toybox 不带 awk，而 Magisk 自带 busybox 有。改成 `$BB awk` 后正常。
另外两个细节：

1. main 表里**没有** `default` 路由（default 在 netd 的 per-network 表），
   开机等待网络不能用 `ip route show | grep '^default '`，要等 `ip -4 addr show wlan0` 出现 `inet`。
2. ZT 接口出现时间不固定（网络就绪前启动要 2 min 以上），所以「补规则」必须放后台子 shell，
   并把子网写进 `/data/local/tmp/zt-subnet.txt`：下次开机先用缓存把规则加上，接口一出现即通。
   规则加好后每 5 分钟复核一次（netd 重启/切网会清掉自定义规则）。
